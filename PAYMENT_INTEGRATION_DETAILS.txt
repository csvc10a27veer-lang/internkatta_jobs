     "phonepeTransactionId": "PHONEPE_ORDER_ID"

================================================================================
                            PAYMENT FLOW DETAILS
================================================================================

STEP 1: PAYMENT INITIATION
---------------------------
1. User selects a course or internship on the frontend
2. Frontend sends POST request to /api/payment/course or /api/payment/internship
3. Backend validates:
   - Course/Internship exists
   - User exists
   - User hasn't already purchased the item
   - Coupon code (if provided) is valid
4. Backend generates unique transaction ID (format: TXN_timestamp_randomString)
5. Backend creates payment record in database with status: PENDING
6. Backend gets PhonePe OAuth 2.0 authorization token:
   - POST to AUTH_TOKEN_URL
   - Request body: client_id, client_version, client_secret, grant_type
   - Response: access_token
7. Backend creates payment payload:
   {
     "merchantOrderId": "TXN_...",
     "amount": amount_in_paise, (amount * 100)
     "paymentFlow": {
       "type": "PG_CHECKOUT",
       "merchantUrls": {
         "redirectUrl": "https://InternKatta.gradezy.in/payment/callback?transactionId=..."
       }
     }
   }
8. Backend calls PhonePe v2 API:
   - POST to BASE_URL/v2/pay
   - Headers: Content-Type: application/json, Authorization: O-Bearer {access_token}
   - Body: payment payload
9. PhonePe returns redirect URL
10. Backend returns payment URL to frontend
11. Frontend redirects user to PhonePe payment page

STEP 2: PAYMENT PROCESSING
---------------------------
1. User completes payment on PhonePe
2. PhonePe processes payment
3. PhonePe sends callback to backend:
   - POST to /api/payment/callback
   - Body contains payment status and details
4. Backend processes callback:
   - Finds payment record by merchantOrderId (transactionId)
   - Verifies amount matches
   - Updates payment status:
     - If PAYMENT_SUCCESS: status = COMPLETED
     - If PAYMENT_ERROR: status = FAILED
5. If payment successful:
   - Enrolls user in course/internship
   - Marks coupon as used (if applicable)
   - Updates payment record with completion date
6. PhonePe redirects user to frontend redirect URL
7. Frontend checks payment status and shows success/failure message

STEP 3: PAYMENT STATUS CHECKING
--------------------------------
1. Frontend can poll payment status using transaction ID
2. GET /api/payment/status/:transactionId
3. Backend checks database for payment record
4. If status is PENDING, backend queries PhonePe API for latest status
5. Backend updates payment record if status changed
6. Returns current payment status to frontend

AUTHENTICATION METHOD:
---------------------
OAuth 2.0 Client Credentials Flow

AUTHORIZATION TOKEN GENERATION:
-------------------------------
1. Request URL: AUTH_TOKEN_URL
2. Method: POST
3. Content-Type: application/x-www-form-urlencoded
4. Request Body:
   - client_id: MERCHANT_ID
   - client_version: SALT_INDEX
   - client_secret: SALT_KEY
   - grant_type: client_credentials
5. Response:
   {
     "access_token": "token_here",
     "token_type": "Bearer",
     "expires_in": 3600
   }

AUTHORIZATION HEADER FORMAT:
----------------------------
Authorization: O-Bearer {access_token}

7. Payment record tracking in database

================================================================================
                        AMOUNT HANDLING
================================================================================

AMOUNT CONVERSION:
------------------
- Database stores amount in Rupees (e.g., 999.00)
- PhonePe API requires amount in Paise (e.g., 99900)
- Conversion: amount_in_paise = amount_in_rupees * 100

AMOUNT VALIDATION:
------------------
1. Frontend sends finalPrice (optional) for validation
2. Backend calculates actual final price:
   - Starts with course/internship price
   - Applies discount if coupon provided
   - Validates against frontend finalPrice if provided
3. Backend verifies amount in callback:
   - Converts database amount to paise
   - Compares with PhonePe callback amount
   - Rejects if mismatch

================================================================================
                        COUPON INTEGRATION
================================================================================

COUPON VALIDATION:
------------------
1. Check coupon exists and is active
2. Check coupon is valid for the course/internship
3. Check coupon hasn't expired (validUntil > current date)
4. Check usage limit not exceeded (usedCount < usageLimit)
5. Check user hasn't already used this coupon
6. Calculate discount:
   - Percentage: (price * discountAmount) / 100
   - Fixed: discountAmount
   - Apply maxDiscountAmount if specified
7. Ensure discount doesn't exceed item price

COUPON USAGE:
-------------
- When payment is completed:
  - Add user to coupon.usedBy array
  - Increment coupon.usedCount
  - Save coupon record

================================================================================
                        ERROR HANDLING
================================================================================

COMMON ERRORS & HANDLING:
-------------------------
1. Authorization Token Failed:
   - Error: Failed to retrieve access_token from PhonePe
   - Check: PhonePe credentials, network connectivity
   - Log: Full error response from PhonePe

2. Payment Initiation Failed:
   - Error: PhonePe payment initiation failed
   - Check: Payload format, required fields, authorization token
   - Log: Request payload, headers, PhonePe response

3. Callback Not Received:
   - Check: Callback URL configuration in PhonePe dashboard
   - Verify: Backend endpoint is accessible
   - Check: Network/firewall settings

4. Status Check Failed:
   - Error: Failed to check PhonePe status
   - Check: Transaction ID validity, PhonePe API access
   - Log: Transaction ID, API response

5. Amount Mismatch:
   - Error: Amount mismatch in callback
   - Action: Reject payment, log discrepancy
   - Check: Amount calculation, conversion to paise

6. Payment Record Not Found:
   - Error: Payment record not found for transaction
   - Check: Transaction ID format, database query
   - Log: Transaction ID, database search

================================================================================
                        IMPORTANT NOTES
================================================================================

1. CREDENTIALS SECURITY:
   - Never commit credentials to version control
   - Use environment variables for all sensitive data
   - Keep production credentials secure
   - Rotate credentials if compromised

2. CALLBACK URL CONFIGURATION:
   - Must be configured in PhonePe merchant dashboard
   - Must be accessible from PhonePe servers
   - Must use HTTPS in production
   - Must match exactly (including trailing slashes)

3. AMOUNT HANDLING:
   - Always convert to paise for PhonePe API
   - Always verify amount in callback
   - Store amount in rupees in database

4. TRANSACTION ID:
   - Must be unique for each payment
   - Format: TXN_timestamp_randomString
   - Used to track payment throughout flow

5. PAYMENT STATUS:
   - PENDING: Payment initiated, waiting for user action
   - COMPLETED: Payment successful, user enrolled
   - FAILED: Payment failed or rejected
   - CANCELLED: Payment cancelled by user

6. TESTING:
   - Always test in UAT environment first
   - Use test credentials for development
   - Verify callback URL accessibility
   - Test all payment scenarios

7. ERROR HANDLING:
   - Always log errors with full context
   - Return user-friendly error messages
   - Don't expose sensitive information in errors

8. API VERSION:
   - Currently using PhonePe v2 API
   - Uses OAuth 2.0 authentication
   - Legacy v1 API (checksum-based) is not used
